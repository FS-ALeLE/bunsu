## 3. 앱별 실제 기능 (교육적 의도 중심)

### ② 분수 놀이터 — 1~2차시
- **자유 탐색:** 원·정사각형·직사각형·띠·정육각형·정삼각형 **6종**을 2~12조각으로 똑같이 나누고, 손가락으로 끌며 색칠합니다(정육각형은 2·3·6조각만).
- **[몇 분의 몇일까?] 버튼:** 색칠해도 분수가 바로 보이지 않습니다. 버튼을 눌러야 세로 분수와 "4분의 3"이 나오고 소리로 읽어 줍니다. 교사가 먼저 "몇 분의 몇일까?" 하고 물을 수 있게 수업 확인 후 바꾼 기능입니다. 색칠을 바꾸면 다시 가려집니다. ⚙ 메뉴의 '분수 바로 보이기'로 예전처럼 바로 보이게도 할 수 있습니다.
- **미션 3단계:** 1단계 보고 쓰기(분모부터 숫자 패드로, 분모 2~6) → 2단계 읽고 색칠하기("7분의 4만큼 색칠하세요" + 읽어 주기) → 3단계 같은 분수를 원·띠·사각형 3칸에 모두 색칠 → 도전 모드(정육각형·정삼각형, 분모 12까지).
  - 3번 연속 맞히면 다음 단계로 갑니다.
  - 틀리면 조각에 번호(1, 2, 3…)가 붙는 힌트가 나오고, 같은 문제를 2번 틀리면 정답을 보여 주고 넘어갑니다.
  - 화면에는 '내 탐험 위치'(단계)만 나옵니다.
- **칠판 모드(릴레이):** 도형이 화면 높이의 70%, 글씨는 40px 이상입니다. '분수 카드 뽑기' → 학생이 나와 색칠 → [몇 분의 몇?] · [확인]. 누르는 도형·버튼은 아이들 키를 생각해 **화면 아래쪽**에 있습니다.

### ④ 분수 비교 챌린지 — 3~4차시
- Lv1 그림 있는 분모가 같은 분수 → Lv2 그림 없이 분모가 같은 분수 → Lv3 단위분수 → Lv4 섞기 + 이유 고르기.
- 두 분수 사이 빈칸에 > < = 를 고릅니다. 같은 분수(=)도 가끔 나옵니다.
- 3번 연속 맞히면 레벨이 오르고, **레벨은 내려가지 않습니다**(대신 힌트가 나옴).
- 같은 유형을 2번 틀리면 **띠 모형 힌트**(전체 길이가 같은 두 띠)가 자동으로 나옵니다. 한 문제를 2번 틀리면 정답과 설명("분모가 같으면 분자가 클수록 큰 분수예요")을 보여 줍니다.
- **Lv4 이유:** '분모가 같고 분자가 커서' / '분자가 1이고 분모가 작아서 한 조각이 커서' / '그림으로 확인해서'. 크기 비교가 맞으면 정답으로 처리하고, **고른 이유는 따로 기록해 평가 자료로 씁니다.**
- 화면에는 '내 탐험 위치'(Lv)와 푼 문제 수만 나오고, 순위는 보여 주지 않습니다.

### ⑥ 분수 스피드 배틀 — 5~6차시
- 2·3·4모둠이 전자칠판 앞에 **가로로 나란히** 서서 각자 칸에서 같은 문제를 동시에 풉니다(기본 4칸, 1×4). 손가락마다 처음 닿은 칸을 기억해서 옆 칸 터치와 섞이지 않습니다.
- 라운드:
  - R1 듣고 고르기: 음성 "5분의 2" → 그림 4개 중 고르기, 칸마다 다시 듣기 버튼
  - R2 색칠하기: 같은 분수를 칸마다 다른 모양으로
  - R3 더 큰 분수 고르기
  - R4 카드 3장 끌어서 줄 세우기
- 1·2·3등 표시와 점수(3·2·1점)가 있습니다. 틀리면 그 칸만 2초 흔들리고 "다시 해 볼까?"가 나옵니다. 라운드가 끝나면 교사가 **'설명 보너스 +1'** 을 줍니다(풀이를 말로 설명하게 하는 장치).
- 칸 안에서 누르는 그림·카드·버튼은 칸 아래쪽에 있습니다. 게임이라 기록은 서버로 보내지 않습니다.

### 우리 반 문제은행(② 출제 모드 + GAS) — 5~6차시
- **문제 만들기:** 모양 → 나누기 → 색칠 → 문제 유형 → 정답·힌트 → 미리보기 → 제출.
  - 문제 유형: 분수 쓰기 / 더 큰 분수 고르기 / 똑같이 나누었을까?
  - '똑같이 나누었을까?' 문제는 조각 경계를 끌어 일부러 똑같지 않게 나눌 수 있습니다. 똑같이 나눈 자리에는 점선 안내선이 보이고, 가까이 가면 딱 붙습니다.
  - 학생이 넣은 정답이 그림과 맞는지 앱이 확인합니다("그림을 다시 확인해 볼까?").
  - 사진 문제: 피자·색종이 등을 찍어 문제로 만듭니다. 촬영 화면에 "얼굴이나 이름이 나오지 않게" 안내가 있고, 사진은 학생 기기에서 줄여서 보냅니다.
- **교사 승인:** 교사가 승인한 문제만 공개됩니다. 사진 문제는 승인 전에 교사가 사진을 확인합니다.
- **문제 풀기:** 승인된 문제가 무작위로 나오고, 내가 만든 문제는 나에게 나오지 않습니다. 풀고 나면 출제자 힌트, 좋아요, 한 줄 댓글(40자, 금칙어 필터)이 나옵니다.
- **칠판 TOP3:** 좋아요를 많이 받은 문제 3개를 크게 보여 줍니다(출제자 번호만 표시). 출제 의도 발표에 씁니다.

### 교사 대시보드
- 학급 코드 + 교사 PIN으로 들어갑니다. 30초마다 자동으로 새로고침됩니다.
- 보여 주는 것:
  - ② 미션 단계별 학생 번호
  - ④ 레벨별 학생 번호
  - 오답률 높은 문제 TOP5(3번 이상 풀린 문제)
  - 반 전체 풀이 수·정답률
  - 문제은행 승인/숨김
- **학생용 공개 보기:** 반 전체 합계만 보여 줍니다(개인 번호 없음). 예: "오늘 우리 반은 분수를 모두 ○번 비교했어요"

### 따라하기형 ①③⑤ (claude.ai 채팅 제작)
- **① 똑같이 나누었을까?:** 원·정사각형·직사각형·정삼각형을 똑같이/똑같지 않게 무작위로 나누고 O/X로 판별합니다. '조각 겹쳐 보기' 애니메이션이 있습니다.
- **③ 분수 비교 돋보기:**
  - 나란히 비교: 막대 조각을 눌러 분자를 정할 수 있습니다.
  - 단위분수 계단: 1(전체)부터 8분의 1까지.
  - 함정 피자: 전체 크기가 다른 피자로 비교하는 장면.
- **⑤ 분수 줄 세우기:** 채팅 제작본 그대로입니다.
- ①③은 수업 확인 후 교사 요청으로 일부를 고쳤습니다(6장 표). 보고서에 "채팅 한 번으로 만든 결과물"이라고 쓸 때는 이 점을 함께 밝혀야 정확합니다.

| 모든 웹앱은 HTML 파일 하나짜리 | ①③⑤만 HTML 파일 하나. ②④⑥·문제은행·대시보드는 **여러 파일로 된 웹사이트**(설치·빌드 없이 링크로 열림) |
| GAS는 "시트 사본 제공" | 현재는 **시트 사본 링크가 없고**, 모음 페이지 안내대로 새 시트에 `Code.gs`를 붙여 넣고 `setup` 실행 → 배포 → 주소 붙여 넣기(3단계). 사본 링크를 줄지 교사가 정해야 함 |
| 1~2차시 꿀팁 "두 손가락 확대를 허용한다" | 앱은 확대(두 손가락 줌)를 막아 두었음. 대신 도형이 화면에 크게 나오고 휴대폰·태블릿 크기에 맞춰 배치가 바뀜. 꿀팁 문구를 고치거나 기능을 바꿀지 교사가 정해야 함 |
| AI 도구·배포 플랫폼은 "예: Claude·Gemini, GitHub Pages·Netlify" | 실제: **Claude Code(배포형)**, **claude.ai 채팅(따라하기형)**, **GitHub Pages**, **구글 앱스 스크립트** |

## 6. 바이브코딩 과정 (보고서 핵심 근거)

### 방법
1. **설계(claude.ai, 10-09):** 계획서와 우수 보고서를 검토해 수업 설계안을 만들고, 그 5·6장을 바탕으로 **개발 명세서**(`CLAUDE.md`)를 썼습니다. 명세서에는 수업 장면, 만들 앱, 화면 규칙, 개발 순서 0~8단계, 배포 전 확인 목록이 들어 있습니다.
2. **따라하기형(claude.ai 채팅, 10-10):** 프롬프트 카드로 ①③⑤를 만들었습니다.
3. **배포형(Claude Code, 10-10):** 짧은 요청 몇 개로 명세서 순서대로 만들고 배포했습니다.
4. **현장 확인 후 수정(10-10~11):** 교사가 실제 기기에서 써 보고, 발견한 문제를 **한 문장으로 요청**해 고쳤습니다.

개발 중 AI가 스스로 찾아 고친 것도 있습니다: 도형이 작게 보임, 큰 분모에서 띠가 너무 가늘어짐, 인터넷 재연결 시 기록 전송 멈춤, 승인 화면에서 사진이 안 보임, 단계 변경 기록이 풀이 수에 섞임. 원본 기록은 `docs/process.md`에 있습니다.

### 설계안의 '바이브코딩 제작 과정' 4단계와의 연결
'장면 정의 → 첫 프롬프트 → 시범 적용과 수정 → 배포'가 실제로 어떻게 진행됐는지 보여 줍니다.
- 장면 정의: 명세서
- 첫 프롬프트: 요청 문장 1~2
- 시범 적용과 수정: 위 표
- 배포: GitHub Pages, QR

## 7. 학교 현장을 고려한 설계 원칙

- **로그인·이름 없음:** 학생은 학급 코드 + 번호로만 들어옵니다. QR에 학급 코드가 들어 있어 번호만 누르면 됩니다.
- **개인정보:**
  - 이름·얼굴을 저장하지 않습니다. 사진은 촬영 안내와 교사 승인을 거칩니다.
  - 학생 화면 어디에도 다른 학생의 순위·이름이 나오지 않습니다.
  - 공개 저장소에는 학생 자료가 없습니다(기록은 교사 개인 구글 시트에만).
- **학교망 대비:** 외부 서버(CDN)·외부 글꼴을 쓰지 않습니다. QR 코드도 프로그램 안에서 직접 만듭니다.
- **설치 없음:** 링크만 열면 됩니다. 구글 시트를 연결하지 않아도 모든 앱이 동작합니다.
- **교과서 표기:** 분수는 세로(분자 위, 가로선, 분모 아래)로만 쓰고, "○분의 ○"로 읽어 줍니다.
- **"전체가 같아야 비교할 수 있다":** 모든 모양의 전체 넓이를 같게 맞추었습니다. 조각 넓이가 같은지는 확인용 페이지가 자동으로 계산합니다.
- **오답을 벌처럼 보이지 않게:** 빨강 대신 노랑 '다시 해 볼까?'를 씁니다. 효과음은 교사가 끌 수 있습니다.
- **전자칠판:**
  - 글씨는 40px 이상이고, 누르는 것은 아이 손이 닿는 아래쪽에 둡니다.
  - 동시 터치 확인 페이지(`tests/multitouch.html`)로 교실 칠판이 4점 이상 동시에 인식하는 것을 먼저 확인했습니다.
- **화면 집중:** 설정은 ⚙ 안에 숨기고 도형과 분수를 크게 보여 줍니다.

## 8. 확산 방안 (실제로 준비된 것)

- **배포형 바로 쓰기:** https://fs-alele.github.io/bunsu/ 에서 학급 코드를 넣으면 학생용 링크와 QR이 만들어집니다. QR 크게 보기로 전자칠판에 띄울 수 있습니다.
- **우리 반 기록 모으기(3단계, 모음 페이지에 안내):**
  1. 구글 시트 → 확장 프로그램 → Apps Script에 `gas/Code.gs`를 붙여 넣고 `setup`을 실행합니다.
  2. 웹 앱으로 배포합니다(실행: 나 / 액세스: 모든 사용자). settings 탭의 교사 PIN을 바꿉니다.
  3. 주소를 모음 페이지 '선생님 설정'에 붙여 넣습니다.
- **고쳐 쓰기:**
  - 공개 저장소를 복사해 자기 GitHub Pages에 올리면 됩니다. 빌드·설치가 필요 없고, 파일 안 설명이 한국어입니다.
  - 분모 범위는 설정이나 주소 뒤 `?maxd=8`로 줄일 수 있습니다.
- **따라하기형:** 설계안 6장의 프롬프트 카드 ①③⑤와 '우리 반에 맞게 고치는 한 문장 프롬프트'.
- **바이브코딩 따라 하기:** 명세서(`CLAUDE.md`)와 6장의 요청 문장 표가 다른 교사의 출발점이 됩니다.

## 10. 보고서 형식 참고

설계 대화에서 정리한 2025 우수보고서(사회과) 형식의 목차는 다음과 같습니다. 2026 참고 보고서와 비교해 최종 형식을 정합니다.

> 1 수업 의도 → 2 관련 교육과정 → 3 차시 지도 계획 → 4 주사용 수업 도구의 이해 → 5 차시별 교수·학습 과정안(+수업 운영 꿀팁) → 6 활동 내용 및 결과·참고자료 → 7 과정 중심 평가 → 8 결론 및 제언 → 부록(활동지)

심사 기준별 근거 배치는 설계안의 '심사 기준별 강조 포인트' 표를 따릅니다.
- 목적 및 주제의 적절성
- 내용의 적절성 및 충실성
- 내용의 참신성 및 체계성
- 현장 적용 및 확산 가능성
